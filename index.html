DTR Regime Switching

Sole-author preprint, “Deterministic Regime Switching and Feasibility Inversion in Dynamic Tensor Rematerialization”, with its reproducibility package.

Question

DTR trains a network inside a memory budget by evicting tensors and recomputing them on demand. This package replays the public DTR prototype simulator across many budgets to see where runs complete, fail, or slow down.

What I built

Sweep and probe scripts, victim-order tracing, and committed raw results as JSON files next to the two figures below. It covers two recorded traces (LSTM-128 and ResNet-32) and four eviction heuristics: DTR, AbESize, AbEStale and AbE.

Method

ResNet-32 is swept over 51 budget ratios, from 0.100 to 0.150 of the unconstrained peak in steps of 0.001, with three repeats each. Failures are classified as out-of-memory, thrashing or recursion limit. The out-of-memory band was also reproduced in independent OS processes.

Evidence

The sweep shows an out-of-memory band at ratios 0.102 to 0.106 with completed runs on both sides. In the probe, 0.101 completes, 0.104 runs out of memory and 0.107 completes again, so a smaller budget can succeed where a larger one fails. Across completed runs, overhead moves in steps between roughly 1.8× and 3.3× baseline. On the LSTM trace, the preprint reports that budgets differing by 0.10% of peak memory select execution regimes whose overheads differ by up to 7.3×, driven by repeated re-eviction of the same tensors.

Boundary

Every result comes from the simrd simulator replaying recorded traces. None of it is a claim about a real GPU training runtime, and the preprint leaves reproduction in a production runtime to future work.

Follow-up

An exploratory follow-up, dtr-stability, characterises feasibility holes and evaluates eviction policies for robustness across workloads and memory budgets. It has a frozen evaluation protocol, is separate from the preprint, and reports no outcome numbers yet.

Veridex

An AI strategy red-team: paste a strategy document and five independent critics return a structured critique in parallel.

What I built

A tool that runs five critic lenses over a strategy document — pre-mortem, unit economics, adversarial competitor, execution risk and evidence audit — and streams a structured critique back to the user as each pass completes. Each lens returns a short synthesis and 2–7 ranked flaws, each with a title, severity and the sharpest question the author must answer next.

Architecture

A FastAPI backend runs the five passes concurrently with asyncio.gather and streams pass_started / pass_completed / done events over Server-Sent Events to a single-page Next.js frontend. Frontend on Vercel, backend on Render.

Reliability

Every critic pass is validated against a strict Pydantic schema. One retry follows a schema failure, with a corrective nudge; a second failure raises an error rather than falling back silently. Rate limiting is 5 critiques per IP per hour, in memory on the backend.

Boundary

Stated in the repository as v1 non-goals: no accounts or stored user data, no multi-turn conversation, no improvement suggestions — Veridex challenges a strategy, it does not revise one. The in-memory rate limiter resets on every backend restart, and PDF export is deferred.

Moon & Sun

A multilingual messaging PWA for private two-person conversations, with AI translation between each pair’s languages.

What I built

An invite-only progressive web app with private two-person conversations, real-time updates and AI translation for English–Ukrainian/Russian and English–Spanish pairs.

Design choices

Senders see a translation preview before they send and can correct it manually. Each pair keeps its own “Our Language” preferences for terminology, slang and communication style.

Architecture

Supabase Auth, PostgreSQL, Realtime, Row-Level Security and Edge Functions, with translation calls to OpenAI made server-side. The front end is React, deployed on Vercel.

Boundary

The source is in a private repository, so this account of the architecture cannot be checked on GitHub. Access is by invitation, and no translation-quality or usage figures are reported here.

PaperTrail

Question answering over ML-systems papers, with every answer tied to the passage it came from.

Problem

Answers about rematerialization, offloading and distributed training papers are only useful if they cite the exact passage, and only trustworthy if every retrieval change is scored.

Approach

Evaluation comes first. Each retrieval change is scored against a hand-labelled question set, and the CI gate (eval/gate.py) fails the build if quality regresses. Gold labels carry verbatim evidence quotes, so they survive re-chunking. Answer faithfulness uses an LLM judge that is spot-checked against hand labels.

Built so far

23 papers ingested as 1,077 chunks, 74 draft gold questions including unanswerable and cross-paper cases, and Docker and CI in place.

Next

Compare BM25, vector search, hybrid retrieval with reciprocal rank fusion, and hybrid plus a cross-encoder reranker on recall@5 and MRR. This stage has not started.

Evidence

None reported yet. The repository leaves every cell of its results table empty until the labels are verified, and I am keeping this page the same way.

Boundary

The 74 questions are drafts, so any score computed from them is provisional. The grounded-answer API with citations and a refusal path (/ask) is a stub.

NeuroLight-AI

Learned one-step predictive control of a simulated 64-neuron population, compared with PI feedback and a linear ARX baseline.

Question

Can a history-conditioned learned controller track a target firing rate better than PI feedback, and better than an information-matched ARX+RLS baseline, when the plant’s sensitivity shifts without warning?

What I built

64 heterogeneous leaky integrate-and-fire neurons driven by light intensity. A small MLP (3 inputs, 32 tanh units) predicts the next firing rate, written in NumPy with backpropagation and Adam for 700 epochs. The controller scores 101 candidate intensities and picks the one with the lowest predicted tracking error plus penalties.

Design

Splits are by whole trajectory: 20 training, 5 validation and 5 test circuits. Stages are labelled exploratory, development or confirmatory. Protocol files are frozen before confirmatory runs and spent seed sets are not reused for tuning. An aborted launch caused by an argument-order bug is documented in a correction note.

Evidence

In the v0.1 baseline, the learned controller has the lowest tracking error at nominal and doubled noise, using slightly more average light than PI (0.376 against 0.367 at nominal noise). Next-step prediction RMSE on held-out data is 0.802 Hz for the MLP, 0.934 Hz for linear regression and 7.899 Hz for persistence.

Boundary

Practice

  • Results sit beside the code that made them.The DTR package commits raw JSON results and the scripts that regenerate its figures.
  • Findings are reproduced before they are reported.The DTR out-of-memory band was rerun in independent OS processes.
  • Protocols are locked before confirmatory runs.NeuroLight-AI freezes protocol files, retires spent seed sets and documents its one aborted launch.
  • Unverified numbers stay marked.PaperTrail keeps its draft labels provisional and its results table empty until they are checked.
